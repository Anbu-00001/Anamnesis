# Code of conduct

Anamnesis is a tool for being honest about what you believed before you knew. This page
asks the same of the people around it.

## Using it and forking it

Anyone may use Anamnesis, change it, fork it and ship it, for any purpose. The
[MIT license](LICENSE) is what governs that, and it asks one thing: keep the copyright and
permission notice in your copies.

If you build your own version of the same idea, the project asks for three things more,
as a courtesy rather than a legal condition:

- **Cite it.** Say where your version came from, in your README and wherever you describe
  the work. [CITATION.cff](CITATION.cff) has the details, and GitHub's "Cite this
  repository" link formats them for you.
- **Say what you changed,** especially if you changed what a number means: how a claim is
  scored, when a verdict is given, or what counts as evidence.
- **Make it yours.** Write your own docs, name it your own name, and shape it for the
  people you are building it for. Don't present a fork as this project, and don't quote
  this project's measurements as if they were made on yours.

## How we treat each other

This applies to issues, pull requests, discussions, reviews, and anything posted in the
project's name.

- Argue with the code and the numbers, not with the person. "This test can pass when the
  suite fails, here is the run" is the kind of criticism this project exists for.
- Assume the other person is trying to get it right. Ask before concluding they aren't.
- Disagree as plainly as you like. Insults, slurs, harassment, threats, sexual content,
  and personal attacks are not disagreement, and they are not welcome here.
- Don't post anyone's private information, and that includes their ledger. A prediction
  record shows how someone thinks; share yours if you want to, never someone else's.
  `ana export --anonymize` exists for sharing the numbers without the content.

## Honesty in the work

The tool refuses to call anyone calibrated on the strength of a quiet test. Contributions
are held to the same standard.

- Report what you measured, how, and on what. A simulation is described as a simulation,
  under its own assumptions.
- A null result is a result. Report it as one.
- If you change a test so that it passes, say why the old expectation was wrong.
- If a tool or a model wrote most of a contribution, say so in the pull request. This
  project was built with Claude Code and says so in its README; that is the standard, not
  an exception.

## Reporting a problem

If someone's conduct here is a problem, tell the maintainer,
[@Anbu-00001](https://github.com/Anbu-00001), privately, by email at
[anbuchelvannew@gmail.com](mailto:anbuchelvannew@gmail.com). Please don't report it in a
public issue.

You will get an acknowledgement within about a week. Reports are kept confidential, and
the person reported will not be told who made the report. If the report is about the
maintainer, use GitHub's own "Report content" link on the comment or the profile instead.

What can happen, depending on what happened and whether it repeats:

- a private word;
- edited, hidden or deleted comments;
- a temporary block from the project;
- a permanent block.

Security vulnerabilities are not conduct reports. They go through
[SECURITY.md](SECURITY.md).
